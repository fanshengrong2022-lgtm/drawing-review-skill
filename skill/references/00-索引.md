# 方法库索引（先看这个）

> **本 Skill 的判定规则、审图条目、方法细则全部在云端。**
> 本地文件只给骨架与流程；**具体怎么做，必须从云端取**。

## 一、五类能力，各在哪

| 要什么 | 怎么取 | 本地有吗 |
|---|---|:-:|
| **判定规则**（该不该提）| `--rules --ids R14,R5` | 只有名字和动作 |
| **审图条目**（该查什么）| `--checklist --profession 装修 --limit 20` | ❌ 云端 |
| **五问预检**（一条问题判死活）| `--review --text "问题描述"` | ❌ 云端 |
| **方法细则**（怎么审）| `--method <主题> <段号>` | ❌ **云端** |
| 环境安装 / 工作边界 / 格式样板 | 本地 `01` / `02` / `07` | ✅ |

## 二、方法库的五个主题

| topic | 内容 | 段数 |
|---|---|:-:|
| `tech-path` | 技术路径（图纸→可读数据、三条路线、已知限制）| 8 |

| `self-check` | **收工覆盖自查**（覆盖清单 / 漏项循环 / 分身 / 拷问官）| 13 |

| `wording` | 表述规范（三种句式 / 五条硬要求 / 禁止清单）| 7 |

## 三、怎么取（两种方式）

**方式 A · 命令行**

```bash
# 先看有哪些主题
python scripts/ask_api.py --method list

# 看某个主题分了哪几段
python scripts/ask_api.py --method five-steps --outline

# 取某一段正文
python scripts/ask_api.py --method five-steps 3
```

**方式 B · 直接打接口**

```bash
curl -X POST "$DRAWING_REVIEW_API/v1/method" \
  -H "Content-Type: application/json" \
  -H "X-API-Key: $DRAWING_REVIEW_KEY" \
  -d '{"topic":"five-steps","part":3}'
```

## 四、⭐ 三条铁律

### 1. 动手前必须取，不许凭印象

每做一步、每写一类内容，**先取对应的段**。
凭印象做出来的东西，句式不对、表格列不对、清单缺项 —— 等于白干。

### 2. 取到什么就按什么做

**表格列、句式、清单项、分级标准，全部照云端返回的来。**
不许自己发挥、不许"我觉得这样更好"。

### 3. 取不到就停

无 Key / 网络断 / 接口 402 / 接口超时 →
**明确告诉用户：「方法库取不到（原因），无法继续」，然后停下。**

⛔ **绝对不许**：自己编一套方法顶上、假装取到了、跳过某一步直接出报告。

## 五、环境变量（只需配一个）

```bash
export DRAWING_REVIEW_KEY="<向作者申请的 Key>"
# 地址已内置，一般不用配
```

没有 Key 时，`--health` 能通（探活），其余全部返回 402。
联系方式见 `SKILL.md` 的「使用前须知」。
