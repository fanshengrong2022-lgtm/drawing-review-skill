# 第五部分 · 质量纪律（12 条）

> **本文件只列纪律名称与「违反即无效」的红线。每条的判定细则、正反例、句式样板在云端方法库。**
> 取用方式见 `references/00-索引.md`。

## 12 条纪律（名称 + 一句话）

| # | 纪律 | 一句话 |
|:-:|---|---|
| 1 | 必须带定位 | 每条问题带图号 + 轴线/区域，禁止"某处""部分区域" |
| 2 | 禁止编造 | 数值、条文号不许编；不确定标【待人工复核】+ 置信度 |
| 3 | 穷尽不抽样 | 甩项、矛盾、缺项必须 100% 列全 |
| 4 | 缺图先声明 | 缺什么图就写"因缺 XX 图，本项无法执行" |
| 5 | 变更区优先 | 有修订云线 / 版本标记的区域优先查 |
| 6 | ⭐⭐ **否定性结论必须交代依据** | 说"没有/未找到"必须给检索范围 |
| 7 | ⭐ **数字变化必须交代口径** | 统计口径变了要说明 |
| 8 | ⭐ **必须带「分册 / 部位」前缀** | 跨册项目尤其重要 |
| 9 | 禁用自造代号 | 一律用真实文件名 / 真实编号 |
| 10 | 冲突类必须分行列出 | 各处分别是什么，一行一处 |
| 11 | 大样类必须写明"哪一类大样" | 不许笼统说"大样不符" |
| 12 | 否定性结论的固定句式 | 结论 + 检索范围，照抄句式 |

## ⚠️ 红线

**违反上面任意一条 → 该条输出视为无效，必须重写。**

不是"建议遵守"，是**不合格就不许交**。

## 怎么取细则

第 6、7、8、12 条最容易做错，取用它们的完整细则和照抄句式：

```bash
python scripts/ask_api.py --method quality-rules --outline
python scripts/ask_api.py --method quality-rules 3    # 纪律 6 细则
python scripts/ask_api.py --method quality-rules 10   # 纪律 12 句式
```

**写报告前必须取一次——凭记忆写，一定漏东西。**

## 纪律 14：每条问题必须标「规范类 / 施工视角」两列

**一句话：让人一眼看出 —— 这条是「规范不让」，还是「老法师知道会出事」。**

两条来源完全不同的东西混在一张表里，看的人没法判断该不该照着改：
- 规范类 = **不改过不了审、过不了验收**；
- 施工视角 = **不改现场会返工、会赔钱、会扯皮**。

### 问题清单表格固定两列（放在「问题」与「依据」之间）

```markdown
| 编号 | 严重度 | 部位 / 图号 | 问题 | 规范类 | 施工视角 | 依据 | 建议 |
|:-:|:-:|---|---|:-:|:-:|---|---|
| 例-01 | A | 【公区·首层】DI1.00 | 地漏只画符号，未注水封深度 | 是（GB 50242 第5.2.5条） | 是（返臭，交付投诉最高） | … | … |
| 例-02 | B | 【户内】02设计说明 | 三册同引 GB50210-2018 与 2001 | 是（版本废止） | 否 | … | … |
| 例-03 | C | 【公区】墙面大样 | 节点未引内装图集页次 | 否 | 否 | … | … |
```

### 填法（只有三种合法组合）

| 规范类 | 施工视角 | 含义 | 处理 |
|:-:|:-:|---|---|
| 是（带条号） | 是（带后果） | 既违规又会出事 | ✅ 进正文，**排最前** |
| 是 | 否 | 纯合规/验收问题，现场做法不受影响 | ✅ 进正文，进「合规」段 |
| 否 | 是 | 规范没直接规定，但现场会出事（通病/经验） | ✅ 进正文，进「施工风险」段，**依据栏写清是经验还是通病来源** |
| **否** | **否** | 既无规范依据、又无现场后果 | ⛔ **不许进正文**；确有必要留痕的，单列「图纸规范性问题」附录，并注明"不影响施工" |

> ⭐ **第四种情况就是"吹毛求疵"的闸门。**
> 引错图集号、编号写法不统一、措辞不严谨 —— 这些两个都填"否"，别占正文。
> 真要提，进附录，别让用户以为这些和"会返工"是一回事。

### 三列判定口径（照这个判，别自由发挥）

| 列 | 判"是"的标准 | 判"否"的标准 |
|---|---|---|
| **规范类** | 能落到**现行**规范 / 标准 / 图集的**具体条文或表号**（写出编号） | 只能落到"行业做法""经验值""某地要求"，或根本查不到条文 |
| **施工视角** | 不处理会在**施工 / 交付阶段**造成：返工、返修、索赔、工期损失、责任扯不清、验收被卡 | 只影响图纸规范性 / 观感口径，现场照常能做 |

### 报告摘要必须同时报三个数

```markdown
本次共 N 条：规范类 X 条 ｜ 施工视角 Y 条 ｜ 两者都是 Z 条
（另有「图纸规范性问题」附录 W 条，不影响施工，仅供设计参考）
```

> ⛔ 不许只报总数。**只报总数，用户分不清哪些必须改、哪些看看就行。**

### 为什么单独立成纪律

实测教训（2026-11-01）：S2 一套图审出 32 条，其中被独立复核推翻 8 条、
剩下 15 条里真正"施工要管的"约 13 条、纯文档瑕疵 1 条。
**条数一样多，价值差一个量级 —— 但混在一起看不出差别，用户第一反应是"吹毛求疵"。**
