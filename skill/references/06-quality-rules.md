# 第五部分 · 质量纪律（12 条）

> **本文件只列纪律名称与「违反即无效」的红线。每条的判定细则、正反例、句式样板在云端方法库。**
> 取用方式见 `references/00-索引.md`。

## 12 条纪律（名称 + 一句话）

| # | 纪律 | 一句话 |
|:-:|---|---|
| 1 | 必须带定位 | 每条问题带图号 + 轴线/区域，禁止"某处""部分区域" |
| 2 | 禁止编造 | 数值、条文号不许编；不确定标【待人工复核】+ 置信度 |
| 3 | 穷尽不抽样 | 甩项、矛盾、缺项必须 100% 列全 |
| 4 | 缺图先声明 | 缺什么图就写"因缺 XX 图，本项无法执行" |
| 5 | 变更区优先 | 有修订云线 / 版本标记的区域优先查 |
| 6 | ⭐⭐ **否定性结论必须交代依据** | 说"没有/未找到"必须给检索范围 |
| 7 | ⭐ **数字变化必须交代口径** | 统计口径变了要说明 |
| 8 | ⭐ **必须带「分册 / 部位」前缀** | 跨册项目尤其重要 |
| 9 | 禁用自造代号 | 一律用真实文件名 / 真实编号 |
| 10 | 冲突类必须分行列出 | 各处分别是什么，一行一处 |
| 11 | 大样类必须写明"哪一类大样" | 不许笼统说"大样不符" |
| 12 | 否定性结论的固定句式 | 结论 + 检索范围，照抄句式 |

## ⚠️ 红线

**违反上面任意一条 → 该条输出视为无效，必须重写。**

不是"建议遵守"，是**不合格就不许交**。

## 怎么取细则

第 6、7、8、12 条最容易做错，取用它们的完整细则和照抄句式：

```bash
python scripts/ask_api.py --method quality-rules --outline
python scripts/ask_api.py --method quality-rules 3    # 纪律 6 细则
python scripts/ask_api.py --method quality-rules 10   # 纪律 12 句式
```

**写报告前必须取一次——凭记忆写，一定漏东西。**
