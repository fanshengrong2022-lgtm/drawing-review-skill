# 审图 Skill

> **出品**：范工AI实战 ｜ **许可**：CC BY-NC-SA 4.0
> **本地只放流程骨架**；判定规则、条目库、方法细则全部在云端，按需取用 —— 见 `references/00-索引.md`。
> **方法库取不到时不许自己编，必须停下来问用户**。
>
> 🚀 **接到「帮我审一套图」这类请求，直接跳 §3.0 默认剧本**：跑 `prep.py` → 取三件套 → 分线逐跑（每条线派分身）→ 自检 → 出报告。
> **用户不需要教你流程，你也不需要问他流程。** 他只负责说「图纸在哪、审哪几个专业、要不要脱敏」。

## 一、这套东西能给你什么（先看这 6 行）

审图前对图，四个动作：**定标准 → 叠图 → 核冲突 → 出报告**，最后收口自查防漏项。

产出物是**一份能直接拿去会审的《预审报告》**：
三张汇总表 ＋ 12 列销项表 ＋ 6 张兜底清单 ＋ **建议层** ＋ **Z 类（AI 能力外）**

> **用户只用说三句话**：图纸在哪 / 审哪几个专业 / 报告要不要脱敏。
> 剩下的按 **§3.0 默认剧本**自动走完，不用他学话术。
>
> **每条线内部派分身**（主审 / 拷问官，方法见云端 4.7/4.8），**拷问官必须推翻过至少 1 条** —— 见 **§3.5**。
> 没有「被推翻的判断」这一节的报告，视为未完成深审。

**适用**：房建各专业 + 市政道路 / 排水 / 桥梁 的图纸会审预审 ｜ 施工图自查 ｜ 跨专业界面核对 ｜ 物料书与图纸对账。

## 三、怎么用：**开工必取，不许跳过**

> ⛔ **这一节是硬要求，不是建议。**
> 本 skill 的方法正文与判据全部在云端（凭 Key 取）。**不取 = 手上没有判据 = 审出来只有图号、目录、清单数量差**，
> 报告会自动降级成"结构审"，客户一看就知道没审进去。
>
> **取了才有能力，不取就是空壳。**

### 3.0 用户只说三句话时的默认剧本（最常见，照做就行）

> **大多数用户不会说"请分线""请派分身"。他只会说：**
> 「装好了」→「图纸在 X，只审道路和排水，报告别出现项目名」→「开始吧」。
>
> **这三句话就够了。你不要反问，直接按下面六步走。** 每一步只报一行，不要长篇汇报。

| 步 | 你做什么 | 报给用户的一句话 |
|:-:|---|---|
| **0** | 没有 `00_预处理报告.md` 就先跑：`python scripts/prep.py --src "<图纸目录>" --out "<输出目录>"`（一条命令做完 DWG→DXF→文字提取→体检→分母） | 「预处理：N 张 / M 万字 / X 秒，失败 Z 张」 |
| **1** | 取开工三件套（见 3.2），报开工三句话 | 「分母 N；分 M 条线；预计 K 轮」 |
| **2** | 四类资料齐备点名；缺的写进《未执行清单》，**不要求用户补** | 「资料齐 X 类，缺 Y 类，按已有资料审」 |
| **3** | **分线逐条跑**：按云端 4.8 的方法分线（见下），一条跑完再跑下一条；**每条线内部派 2~3 个分身**（见 3.5） | 每条线一行：「第 N 条线完成：查到 X 条，A 级 Y 条」 |
| **4** | 四条跑完自问三句：**这套图审完了吗 / 有没有漏项 / 有没有该做没做的**，该补的补 | 「自检：补 X 条，未执行 Y 项」 |
| **5** | 出报告（按 `wording` + `quality-rules`），交付前过五问预检（`--review`） | 「报告已出：N 条，A 级 M 条，档位 X」 |

**三条不许**：

- ⛔ **不许问"要不要先转换图纸"** —— 直接转，转完报数
- ⛔ **不许把"资料缺失"当停工理由** —— 记进《未执行清单》，继续审
- ⛔ **不许一条线跑到一半跳去另一条** —— 跑完一条再下一条（分线是为了不遗漏，不是为了显摆）

**外加一条最费时间的错**：

- ⛔ **不许自己写 DWG→DXF 转换代码，也不许自己写文字提取脚本。**
  `scripts/prep.py` 已经做好了（含递归进块、孤立块分离、六类分母）。
  重写一遍只会慢 30~40 分钟，而且十有八九漏掉块内文字——那正是"读不到 ≠ 没有"翻车的地方。
  **只有当 `prep.py` 确实跑不起来时，才允许自己写，并必须在报告里写明原因。**

**为什么强调"跑完一条再下一条"**：一条线跑到一半切走，等于四条线都只做了一半。
逐条闭环，每条都能单独交差，最后合并才不返工。

#### 分线怎么分：**从云端取，不要自己发明**

```bash
python scripts/ask_api.py --method self-check 10   # 4.8 干活分线
```

云端给了三种切法，**默认用「按检查动作」**（叠图线 / 核冲突 a~d 线 / 双边对应专项线 / 该有而无扫描线）；
只有图纸特别多时才考虑按卷册。

**两条实测教训（云端没有，这里补上）：**

⛔ **不要图省事按册分线**（一册一条）。实测：按册分 4 条线跑完 4 册，只查出 27 条，
且**几乎全是「技术内容」一个维度**；图号目录、跨专业界面、计量对账**三个维度一条都没做**。
按检查动作分线，才能把维度铺开。

✅ **跨图比对必须独立成线**（云端 4.8 里也写死了）。区域线一肩挑十几个动作时，
最先被牺牲的一定是最耗时那个 —— 而"同一部位跨图逐格比对"正是最耗时、最容易只报"叠了 2 组"就交差的那个。

**项目小、时间紧时可以合并检查动作**：叠图 + 跨图比对合成一条"比对线"，核冲突 + 计量合成一条"内容线"，最少两条。但 ⛔ **跨图比对不许省**。

### 3.1 开工必取三件套（不取不许开工）

```bash
python scripts/ask_api.py --method preparation --all    # 开审准备（7 段）
python scripts/ask_api.py --method five-steps  --all    # 执行五步（6 段）
python scripts/ask_api.py --method self-check  --all    # 收工自查（15 段）
```

三次调用拿全（约 4.1 万字）。**在读完这三份之前，不许开始看图。**

| 缺哪一份 | 后果 |
|---|---|
| 没取 `preparation` | 不知道要立分母、不知道要四类资料点齐 |
| 没取 `five-steps` | 不知道五步顺序，容易直接跳到"看图找问题" |
| 没取 `self-check` | 不会分线、不会自查、不会派拷问官 → 单线摊薄、漏项 |

### 3.2 审图中按需取（不要一次全拉）

| 你在干什么 | 取什么 |
|---|---|
| 写问题表述前 | `--method wording --all`（7 段） |
| 报告定稿前 | `--method quality-rules --all`（10 段） |
| 判「这条缺该不该报」 | `--method judgement --all`（8 段） |
| 图纸转换遇到问题 | `--method tech-path --all`（9 段） |
| 不确定这套图属于哪一类 | `--method routing --all`（8 段） |
| 市政项目开工 | `--method municipal-route --all`（11 段） |

### 3.3 判据：按章节逐章取，不许只查一两个关键词

```bash
# ① 先拿大纲：这套图涉及的专业分几章、每章多少条
python scripts/ask_api.py --checklist --profession 排水 --outline

# ② 逐章取条目（每章一次，单次最多 200 条）
python scripts/ask_api.py --checklist --chapter "P3 管道" --limit 200

# ③ 条目多于一页时按 next_offset 翻页，翻到 next_offset 为 null 为止
python scripts/ask_api.py --checklist --chapter "P3 管道" --limit 200 --offset 200
```

> ⛔ **只查关键词 = 只查到你能想到的**。大纲保证"该查的章一个不漏"，关键词只用来定位。

### 3.4 技术内容审查：一次扫一批词（报告里要附这个底账）

```bash
python scripts/ask_api.py --sweep 闭水,闭气,温控,预拱,台背,跌水,倒虹,压浆,预压,围檩,沉泥,盲道,缘石坡道
```

返回每个词在判据库里的命中条数。**用法**：

| 情况 | 判定 |
|---|---|
| 云端有这个判据（n>0），但图纸里搜不到 | ⛔ **缺项，按该条判据的级别报** |
| 云端没有（n=0） | 说明本库未覆盖，**不许硬报，列进"能力外"** |

**报告末尾必须附《技术关键词检索记录》**：检索了哪些词、云端命中数、图纸命中数、结论。**没有这张表 = 视为没做技术内容审查。**

### 3.5 分身：先派角色，再分线（**两件事，别混**）

> **角色分工**和**干活分工**是两回事，别揉在一起：
> · **角色**：主审干、拷问官挑刺 —— 这是"谁审谁挑"
> · **线**：一个分身一条线 —— 这是"各审一块"
>
> **深审和浅审的差别，不在判据多少，在有没有第二个人挑刺。**
> 一个人从头查到尾，会越查越顺、越顺越松，最后全是"看起来没问题"。

**这两件事的具体做法，全部从云端取，包里不给细则：**

```bash
python scripts/ask_api.py --method self-check 9    # 4.7 派分身（角色怎么分、怎么跟 AI 说）
python scripts/ask_api.py --method self-check 10   # 4.8 干活分线（按什么切、几条、怎么交叉核对）
```

> ⚠️ 段落号是 **9 和 10**；云端目录里那两段的标题写的是 4.7 / 4.8，别按 4.7 去当段号取。

**三条硬要求（不管云端怎么写，这三条必须有）：**

1. ⭐ **必须派分身挑刺**，不许让主审自己复查 —— 自己查自己，一定漏。
   分身的关键价值是**它有独立上下文，看不到主审一路怎么想的**，所以不会被带着走。
2. ⭐ **拷问官必须推翻至少 1 条**。一条都推不翻，报告里要写明"复核未发现分歧"并说明原因，**不许假装通过**。
3. **分歧必须留痕**。报告的「**被推翻的判断**」一节就是它。**没有这一节，报告视为未完成深审。**

> ⛔ **不许自己发明角色名和分线名**。云端写"主审 / 拷问官"就按这个叫，写"叠图线 / 核冲突线"就按这个叫。
> **本包只负责逼你去取，不负责替你定。**

### 3.6 报告脱敏（用户提了才做，一句话开关）

有些项目（分公司、涉密、代建）要求报告里不出现真实名称。**用户没说就不用做。**

**触发**：用户说到"不要出现项目名称 / 参建单位 / 地址 / 专名"任一。

**替换规则（固定，不要自创）：**

| 原文 | 写成 |
|---|---|
| 项目名（如 XX 路改造工程） | **本项目** |
| 建设单位 / 设计单位 / 施工单位 / 监理 | 原角色名（不要写公司名） |
| 道路名 / 桥梁名 / 河名 | **道路一 / 桥梁一 / 河道一** |
| 门牌、路名交叉口、行政区 | **项目所在地** |
| 引用图纸 | **只用图号**（DL102 / QL201 / SGPS103），不用文件名里的地名 |

> ⛔ **文件夹名 / 路径名同样算"文件名"** —— 报告里不许出现 `...\XX路平纵横\` 这种路径，
> 一律只写图号。路径里的地名和封面上的地名一样会漏。

**做完自查**：`grep` 一遍报告，确认项目名/公司名/路名出现 **0 次**。搜到一处就是没做完。

> ⚠️ 脱敏只改**表述**，不改**证据**。图号、页码、坐标、数值一律保留原样——
> 否则报告就没法拿去跟设计院对了。

#### 八个脚本一览（`scripts/` 下全部就这些，别漏用）

| 脚本 | 干什么 | 什么时候用 |
|---|---|---|
| **`prep.py`** | **一键预处理**：DWG→DXF → 文字提取（**递归进块**）→ 图纸体检 → 六类分母 → 出 `00_预处理报告.md` | **开审第一步**。一条命令替代"自己写转换脚本"，省 30~40 分钟 |
| **`anti_leak_check.py`** | **发版前防抄自检**：判据编号 / 云端密钥 / 源码文件名 / 项目名 / references 体量，任一命中即**禁止发版** | **每次打包前后必跑**（开发者用，普通审图不用跑） |
| `ask_api.py` | **云端判定引擎客户端**（方法库 / 判定规则 / 审图条目 / 五问预检） | 全程，出报告前必用 `--review` 过五问 |
| `health_check.py` | **图纸体检单**（参照可达 / 污染 / 可读性 / AUDIT 坏图层 / 视口 / 字体） | 开审前第一步，一条命令出报告 |
| **`grid_align.py`** | **轴网对齐 / 叠图基准**（自动提轴号 → 平移归一 → 报偏差 + 轴距序列） | **叠图这一步必须先跑它**，别自己写代码 |
| `report_check.py` | **报告自检 + 档位判定**（A 深度 / B 表层 / C 不通过） | 报告写完、交付前 |
| `extract_hatch_leader.py` | **填充 + 引线提取**（HATCH / LEADER 里的文字） | 数据自检时，"读不到 ≠ 没有" |
| `extract_material_tags.py` | **跨块拼装材料标注提取** | 物料编号与图纸双向核对时 |

#### `anti_leak_check.py` 怎么用（发版前必跑，开发者用）

```bash
python scripts/anti_leak_check.py --pkg 审图Skill_xxx.zip --words 项目名,公司名
```

**判定原则**：不是看有没有编号，是看「**拿走之后能不能自己干**」。

| 检查项 | 命中就是不许发 |
|---|---|
| 判据条目编号（形如「字母+数字-两位序号」） | 判据进包了 |
| 云端密钥 / 服务端源码文件名 | 把服务端带出去了 |
| 真授权码（`skfg-` 开头带真签名的） | 发码台账被打包了 |
| 项目名 / 公司名（用 `--words` 传） | 项目信息泄露 |
| references 体量 > 60 KB | 骨架被换成正文了 |
| 单文件 > 60,000 字符 | 多半是正文 |

**退出码 0 才算通过。**

> 一旦判据进包，别人拿走就能自己跑，**授权码体系当场失效，产品就没了**。

#### `prep.py` 怎么用（开审第一步，一条命令）

```bash
python scripts/prep.py --src "D:\图纸目录" --out "D:\输出目录"
```

产出：

| 路径 | 内容 |
|---|---|
| `00_预处理报告.md` | 人看的汇总：张数 / 字数 / 失败清单 / 体检 / 六类分母 |
| `_dxf/` | 转换后的 DXF（保持原目录结构） |
| `_data/text/*.json` | 每张图的文字项，含 `ty/tx/ly/blk/x/y` |
| `_data/unused/*.json` | **孤立块**里的文字（没插到图上，**不算证据**） |
| `_data/stats.json` | 每张图实体统计 |
| `_data/denominator.json` | 六类单元分母（图号 / 桩号 / 井号 / 材料代号 / 标高 / 图层） |

**三个要点**：

1. **提取递归进块**。有些图的正文全塞在块里，只读模型空间顶层会看到"空壳"。
2. **孤立块单独存**。块有内容但没被插到图上（可能废稿/备份，也可能漏放），
   报告会列出来；**判据核对时不许把它当证据**，但要说明"已查过孤立块"。
3. **失败显式报**。转换失败的张数写进报告，不许当成"没这张图"。

> 需要 ODA File Converter（默认路径已内置，`--oda` 可指定）。

#### `grid_align.py` 怎么用（叠图就靠它）

```bash
# ① 先扫一遍：这套图到底能不能做叠图？
python scripts/grid_align.py --scan "图纸目录" --out 轴网扫描报告.md

# ② 两张图比对（平面↔平面 / 平面↔立面）
python scripts/grid_align.py "图A.dxf" "图B.dxf" --out 轴网偏差报告.md

# ③ 批量：以一张图为基准，比整个目录
python scripts/grid_align.py --base "基准图.dxf" --batch "目录" --out 批量对比.md
```

它会给出**三种判定**，报告里必须照实转述：

| 判定 | 含义 | 你该怎么做 |
|---|---|---|
| **配对模式** | 两图都有轴号，已按轴号配对 | 直接引用偏差数据，写进《跨图比对表》 |
| **间距模式** | 只有轴线没有轴号 | 只能比间距序列，**要明确写"无法按轴号配对"** |
| **无轴网** | 这套图没有轴网 | **明确写"本套图无轴网，不做轴网级叠图"**，这不是失败 |

> **关键概念：平移归一**。两张图原点常常不同（实测某项目整体差 311887.6mm），
> 脚本会先求中位偏移再判残差。**你自己写代码时如果直接比原始坐标，会把全部轴号判成"不一致"。**
>
> ⚠️ **脚本跑不动 ≠ 可以跳过**：跑不了就明说"跑不了"，并把该项列为**未执行**，不许拿"我读过文档"顶替执行结果。

## 四、开工第一件事：把工作边界立清楚

**用户最怕的不是"审不出来"，是"AI 乱翻我电脑"。**
**边界一次说清 —— 用户才敢把图交给你。**

动手前必须确认这四件事（**用户已经给了的，复述确认；没给的，问**）：

| # | 立什么边界 | 怎么做 |
|:-:|---|---|
| **1** | **图纸在哪** | 拿到**图纸目录的准确路径**；工作范围 = 该目录及其子目录 |
| **2** | **产出写到哪** | 约定**一个输出目录**；报告 / 中间文件 / 脚本**全部写这里**。⭐ `prep.py` 跑完最后两行会打印 `【输出目录锁】OUT_DIR=<绝对路径>`，**之后的全部产出必须写到这一行给的目录**，⛔ 不许在会话临时目录 / 文档目录另建「审图输出」之类的目录 |
| **3** | **依赖怎么装** | 只装 `01-setup.md` 列出的那几个库；**不装无关工具、不下载额外东西** |
| **4** | **skill 只读** | ⛔ 不修改 `SKILL.md` 与 `references/` 下的任何文件 |

**三条硬纪律**

- ⛔ **不读图纸目录以外的文件** —— 个人文档、其他项目、桌面、下载夹…… **用户没让你看的，一律不看**
- ⛔ **不往系统目录写东西** —— 桌面 / 文档 / 临时夹都不写，只写约定的输出目录
- ⛔ **越界前先问** —— 确有必要访问其他位置，**先说理由、先征得同意**，再动

**开工第一句，先把边界说出来**：

```
我要审的图在：<路径>
产出我写到：<路径>
除这两处，我不访问其他位置；skill 文件我不改。
```

## 六、九条最容易犯的错（先记这九条）

1. ⛔⛔ **「资料齐备」是审图的粮草** —— 开审前把**四类基础资料**逐个点齐：**① 图纸 ② 物料书 / 材料清单 ③ 工程量清单 ④ 合同 / 承包范围 / 界面依据**。**点的是"文件真的在不在"，不是"文件夹有没有"** —— ⛔ **"目录建好、位置留对、文件没拷进去"是最会骗过眼睛的一种缺**，必须**逐份列文件名 + 数量**核实。**缺任何一类 → 停下来问用户，不许默默往下审**（缺一类 = 对应整条检查线作废，报告缺一整块）；**审的过程中**发现资料不齐，**同样立刻停下报告** —— 不许自行降级、不许把"没资料可查"当结论写进报告。
   ⚠️ **看不到文件的 AI（纯文本对话、无法访问本地磁盘）**：点资料时**必须声明**「以下齐备性依据用户口述的清单判断，我无法核实文件是否真的存在」——**不许把用户的话直接当成"已核实齐全"**，那等于把用户的自信当成你的证据。
2. ⛔⛔ **「图纸本身完整」是审图的地基** —— 开审前必须过**图纸体检**：**跑一次 `scripts/health_check.py`**
   （参照可达性 / 污染 / 可读性 / AUDIT 坏图层 / 视口 / 字体，一条命令出报告）。
   **参照断链 → 那份内容在 CAD 里根本加载不出来 → 图面缺内容。在这种图上审，结论必然打折扣。**
   修复参照的铁律：**只改路径，不绑内容、不重写文件**（细则调 `--method tech-path 2`）
   —— ⚠️ 体检单查不了的两件事（**转换本身丢内容**、**图面看着对不对**）**必须人眼看图**
3. ⛔ **「读不到」≠「没有」** —— 读到 0 条时，**先怀疑自己读错了**：Model 空间 / Paper 空间 / TEXT / MTEXT / **ATTRIB 块属性** / 属性块里的标高 / 未炸开的块 / 图层 / Xref —— **六处排除完再下结论**
4. ⛔ **叠图前先立「轴网基准」** —— **"叠图"是"用轴线把同一处认出来"，不是把图形重叠**。两张图**各自提横轴 / 竖轴 + 轴号** → 选 1 个交点当原点 → 量到位 → 到另一张图**按同一轴号**找同一处。**不同图坐标系不同，禁止靠"图元坐标接近"判断同一处**（见第 2 步（1））
5. ⛔ **「叠了 N 组」不是完成** —— 必须交《跨图比对表》，并报**四个数**：应比 N / 实比 M / 无法核 K / 不一致几格
6. ⛔ **「查无」必须附检索范围** —— 所有否定性结论（查无 / 做不了 / 判正常）都要交代依据
7. ⛔ **「写得对」≠「看得懂」** —— 每条问题必须让**没见过这套图的施工经理一眼看懂**：哪儿 / 什么 / 跟谁冲突 / 要我做什么。**自造代号、只说"不一致"不说各处是什么、不说大样是哪类大样、说"没有"不说查了哪 —— 都属不合格。** 句式调 `--method wording 2`
8. ⛔⛔ **「审了」≠「审够了」** —— 交报告**必附《质量自证表》**：① **六处读取量逐个报数**（Model / Paper / 文字 / 块 / 图层 / Xref——**任何一处全 0 必须解释**）；② **总条数 ＋ 零条目图纸份数 ＋ 条目数÷图纸数**（**零条目 >70%、或比值比上一轮骤降，必须解释**）。**审图最隐蔽的事故不是"审错"，是"审得太少"**——图纸没问题、文件也读得开，但实质没审进去，**客户看不出来，你也未必看得出来**（见第 4 步（7））
9. ⛔⛔ **交报告前必须先声明档位** —— 报告**摘要下方**必须原样出现这两行：
   ```
   叠图：完成
   档位：A 深度审图
   ```
   或
   ```
   叠图：未完成（原因：<一句话>）
   档位：B 表层审图
   ```
   - 写「叠图：完成」必须能追溯到《跨图比对表》的**轴距偏差数据**；只写"完成"却没有偏差数字 = 视为**未完成**
   - **没做叠图也可以交报告**，但必须声明「未完成」，并在报告首页标注「**本报告为表层审图，不建议直接用于会审**」——**不许用"审过了"含糊带过**
   - `report_check.py` 按三档判定：**A 深度审图 / B 表层审图 / C 不通过**。B 档可用于图纸体检，不可用于会审
   - **为什么强制**：实测两个不同 AI 都在完全没做叠图的情况下，报告写成了"已完成全量审图"。**不声明就会默认被当成审过了**

10. ⛔⛔ **开工先报三句话，不报不许往下走** —— 拿到图，第一件事必须说清：

    ```
    ① 本轮分母：<几类单元、各多少个>（例：门 12 樘 / 标高 8 处 / 索引 46 个 / 材料 33 项）
    ② 怎么分线：<分几条线、每条线谁查哪块>（并行，不是一个人从头查到尾）
    ③ 几轮出报告：<第 1 轮交什么、第 2 轮交什么>
    ```

    - **没报分母 = 后面所有"已核 N 项"都没有意义**（分母不清，"查了 20 项"到底是查全了还是查漏了，谁都判断不了）
    - **不分线 = 单线摊薄**，审到后半程就只剩"图号对不对"这种表层问题
    - 分母与分线的做法见 `--method self-check --all` 的 4.1 / 4.8 段

11. ⛔ **报告必须附《技术关键词检索记录》，A 级为 0 必须解释** —— 报告末尾固定两张表：

    | 表 | 内容 | 不做的后果 |
    |---|---|---|
    | **技术关键词检索记录** | 检索了哪些词、云端命中数、图纸命中数、结论（缺项/已覆盖） | 没有 = 视为没做技术内容审查 |
    | **A 级说明** | A 级条目为 0 时，必须写明是「图纸确实规范」还是「判据未覆盖」 | 不写 = 读者无法分辨"图好"还是"没查" |

    - 检索用 `--sweep`，一次一批词
    - **A 级为 0 而技术关键词命中也为 0 → 只有一种解释：审查没做进去，必须回去重审**，不许直接交报告


## 八、边界（这套做什么 / 不做什么）

### ✅ 适用

图纸会审预审 ｜ 施工图自查 ｜ 跨专业界面核对 ｜ 物料书与图纸对账 ｜ 精装 / 公装 / 幕墙深化图预审

### ⛔ 不适用（别硬用，用错场景效果会很差）

| 不适用 | 为什么 |
|---|---|
| **结构受力计算 / 配筋验算** | 需要计算软件与注册结构师，不是读图能解决的 |
| **消防性能化设计评审** | 需要专项资质与模拟软件 |
| **造价审核 / 结算审计** | 属于成本条线，本 Skill 只把清单问题"转出去"，不做造价判断 |
| **需要注册师签章的正式审查** | 本 Skill 出的是**预审报告**，不替代法定审查 |
| **纯扫描件 / 无文字层的图片** | 能读但准确率大幅下降，必须人眼复核（会明确标【需人工复核】）|
| **要求"审出所有问题"** | 不承诺穷尽，承诺的是"该做的动作做完、产物交齐、边界说清" |

### 其他边界

- ⛔ **不含作者本人真实项目迭代出来的经验条目**（那部分属进阶版）
- ⛔ 图纸数据本身缺失 / 损坏 / 是扫描件时，谁都审不了 → **如实进《未执行清单》**，不许装作查了
