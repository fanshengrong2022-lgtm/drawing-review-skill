## 一、这套东西能给你什么（先看这 6 行）

审图前对图，四个动作：**定标准 → 叠图 → 核冲突 → 出报告**，最后收口自查防漏项。

产出物是**一份能直接拿去会审的《预审报告》**：
三张汇总表 ＋ 12 列销项表 ＋ 6 张兜底清单 ＋ **建议层** ＋ **Z 类（AI 能力外）**

**适用**：任何专业的图纸会审预审 ｜ 施工图自查 ｜ 跨专业界面核对 ｜ 物料书与图纸对账。

### 六个脚本一览（`scripts/` 下全部就这些，别漏用）

| 脚本 | 干什么 | 什么时候用 |
|---|---|---|
| `ask_api.py` | **云端判定引擎客户端**（方法库 / 判定规则 / 审图条目 / 五问预检） | 全程，出报告前必用 `--review` 过五问 |
| `health_check.py` | **图纸体检单**（参照可达 / 污染 / 可读性 / AUDIT 坏图层 / 视口 / 字体） | 开审前第一步，一条命令出报告 |
| **`grid_align.py`** | **轴网对齐 / 叠图基准**（自动提轴号 → 平移归一 → 报偏差 + 轴距序列） | **叠图这一步必须先跑它**，别自己写代码 |
| `report_check.py` | **报告自检 + 档位判定**（A 深度 / B 表层 / C 不通过） | 报告写完、交付前 |
| `extract_hatch_leader.py` | **填充 + 引线提取**（HATCH / LEADER 里的文字） | 数据自检时，"读不到 ≠ 没有" |
| `extract_material_tags.py` | **跨块拼装材料标注提取** | 物料编号与图纸双向核对时 |

#### `grid_align.py` 怎么用（叠图就靠它）

```bash
# ① 先扫一遍：这套图到底能不能做叠图？
python scripts/grid_align.py --scan "图纸目录" --out 轴网扫描报告.md

# ② 两张图比对（平面↔平面 / 平面↔立面）
python scripts/grid_align.py "图A.dxf" "图B.dxf" --out 轴网偏差报告.md

# ③ 批量：以一张图为基准，比整个目录
python scripts/grid_align.py --base "基准图.dxf" --batch "目录" --out 批量对比.md
```

它会给出**三种判定**，报告里必须照实转述：

| 判定 | 含义 | 你该怎么做 |
|---|---|---|
| **配对模式** | 两图都有轴号，已按轴号配对 | 直接引用偏差数据，写进《跨图比对表》 |
| **间距模式** | 只有轴线没有轴号 | 只能比间距序列，**要明确写"无法按轴号配对"** |
| **无轴网** | 这套图没有轴网 | **明确写"本套图无轴网，不做轴网级叠图"**，这不是失败 |

> **关键概念：平移归一**。两张图原点常常不同（实测某项目整体差 311887.6mm），
> 脚本会先求中位偏移再判残差。**你自己写代码时如果直接比原始坐标，会把全部轴号判成"不一致"。**
>
> ⚠️ **脚本跑不动 ≠ 可以跳过**：跑不了就明说"跑不了"，并把该项列为**未执行**，不许拿"我读过文档"顶替执行结果。

## 四、开工第一件事：把工作边界立清楚

**用户最怕的不是"审不出来"，是"AI 乱翻我电脑"。**
**边界一次说清 —— 用户才敢把图交给你。**

动手前必须确认这四件事（**用户已经给了的，复述确认；没给的，问**）：

| # | 立什么边界 | 怎么做 |
|:-:|---|---|
| **1** | **图纸在哪** | 拿到**图纸目录的准确路径**；工作范围 = 该目录及其子目录 |
| **2** | **产出写到哪** | 约定**一个输出目录**；报告 / 中间文件 / 脚本**全部写这里** |
| **3** | **依赖怎么装** | 只装 `01-setup.md` 列出的那几个库；**不装无关工具、不下载额外东西** |
| **4** | **skill 只读** | ⛔ 不修改 `SKILL.md` 与 `references/` 下的任何文件 |

**三条硬纪律**

- ⛔ **不读图纸目录以外的文件** —— 个人文档、其他项目、桌面、下载夹…… **用户没让你看的，一律不看**
- ⛔ **不往系统目录写东西** —— 桌面 / 文档 / 临时夹都不写，只写约定的输出目录
- ⛔ **越界前先问** —— 确有必要访问其他位置，**先说理由、先征得同意**，再动

**开工第一句，先把边界说出来**：

```
我要审的图在：<路径>
产出我写到：<路径>
除这两处，我不访问其他位置；skill 文件我不改。
```

## 六、九条最容易犯的错（先记这九条）

1. ⛔⛔ **「资料齐备」是审图的粮草** —— 开审前把**四类基础资料**逐个点齐：**① 图纸 ② 物料书 / 材料清单 ③ 工程量清单 ④ 合同 / 承包范围 / 界面依据**。**点的是"文件真的在不在"，不是"文件夹有没有"** —— ⛔ **"目录建好、位置留对、文件没拷进去"是最会骗过眼睛的一种缺**，必须**逐份列文件名 + 数量**核实。**缺任何一类 → 停下来问用户，不许默默往下审**（缺一类 = 对应整条检查线作废，报告缺一整块）；**审的过程中**发现资料不齐，**同样立刻停下报告** —— 不许自行降级、不许把"没资料可查"当结论写进报告。
   ⚠️ **看不到文件的 AI（纯文本对话、无法访问本地磁盘）**：点资料时**必须声明**「以下齐备性依据用户口述的清单判断，我无法核实文件是否真的存在」——**不许把用户的话直接当成"已核实齐全"**，那等于把用户的自信当成你的证据。
2. ⛔⛔ **「图纸本身完整」是审图的地基** —— 开审前必须过**图纸体检**：**跑一次 `scripts/health_check.py`**
   （参照可达性 / 污染 / 可读性 / AUDIT 坏图层 / 视口 / 字体，一条命令出报告）。
   **参照断链 → 那份内容在 CAD 里根本加载不出来 → 图面缺内容。在这种图上审，结论必然打折扣。**
   修复参照的铁律：**只改路径，不绑内容、不重写文件**（细则调 `--method tech-path 2`）
   —— ⚠️ 体检单查不了的两件事（**转换本身丢内容**、**图面看着对不对**）**必须人眼看图**
3. ⛔ **「读不到」≠「没有」** —— 读到 0 条时，**先怀疑自己读错了**：Model 空间 / Paper 空间 / TEXT / MTEXT / **ATTRIB 块属性** / 属性块里的标高 / 未炸开的块 / 图层 / Xref —— **六处排除完再下结论**
4. ⛔ **叠图前先立「轴网基准」** —— **"叠图"是"用轴线把同一处认出来"，不是把图形重叠**。两张图**各自提横轴 / 竖轴 + 轴号** → 选 1 个交点当原点 → 量到位 → 到另一张图**按同一轴号**找同一处。**不同图坐标系不同，禁止靠"图元坐标接近"判断同一处**（见第 2 步（1））
5. ⛔ **「叠了 N 组」不是完成** —— 必须交《跨图比对表》，并报**四个数**：应比 N / 实比 M / 无法核 K / 不一致几格
6. ⛔ **「查无」必须附检索范围** —— 所有否定性结论（查无 / 做不了 / 判正常）都要交代依据
7. ⛔ **「写得对」≠「看得懂」** —— 每条问题必须让**没见过这套图的施工经理一眼看懂**：哪儿 / 什么 / 跟谁冲突 / 要我做什么。**自造代号、只说"不一致"不说各处是什么、不说大样是哪类大样、说"没有"不说查了哪 —— 都属不合格。** 句式调 `--method wording 2`
8. ⛔⛔ **「审了」≠「审够了」** —— 交报告**必附《质量自证表》**：① **六处读取量逐个报数**（Model / Paper / 文字 / 块 / 图层 / Xref——**任何一处全 0 必须解释**）；② **总条数 ＋ 零条目图纸份数 ＋ 条目数÷图纸数**（**零条目 >70%、或比值比上一轮骤降，必须解释**）。**审图最隐蔽的事故不是"审错"，是"审得太少"**——图纸没问题、文件也读得开，但实质没审进去，**客户看不出来，你也未必看得出来**（见第 4 步（7））
9. ⛔⛔ **交报告前必须先声明档位** —— 报告**摘要下方**必须原样出现这两行：
   ```
   叠图：完成
   档位：A 深度审图
   ```
   或
   ```
   叠图：未完成（原因：<一句话>）
   档位：B 表层审图
   ```
   - 写「叠图：完成」必须能追溯到《跨图比对表》的**轴距偏差数据**；只写"完成"却没有偏差数字 = 视为**未完成**
   - **没做叠图也可以交报告**，但必须声明「未完成」，并在报告首页标注「**本报告为表层审图，不建议直接用于会审**」——**不许用"审过了"含糊带过**
   - `report_check.py` 按三档判定：**A 深度审图 / B 表层审图 / C 不通过**。B 档可用于图纸体检，不可用于会审
   - **为什么强制**：实测两个不同 AI 都在完全没做叠图的情况下，报告写成了"已完成全量审图"。**不声明就会默认被当成审过了**

## 七、执行顺序（一句话）

```
资料点齐 · 环境就绪 → 定立场·划边界 → 数据自检
   → 五步主体（定标准 → 叠图 → 核冲突 → 出报告 → 沉淀）
   → 收工自查（≥2 轮）+ 拷问官独立复核 → **声明档位（叠图完成/未完成）** → 交报告
```

> ⚠️ **机制不受任务规模影响**：重审 / 复跑 / 补审，**都走完整流程**，不许当轻量任务处理。

## 八、边界（这套做什么 / 不做什么）

### ✅ 适用

图纸会审预审 ｜ 施工图自查 ｜ 跨专业界面核对 ｜ 物料书与图纸对账 ｜ 精装 / 公装 / 幕墙深化图预审

### ⛔ 不适用（别硬用，用错场景效果会很差）

| 不适用 | 为什么 |
|---|---|
| **结构受力计算 / 配筋验算** | 需要计算软件与注册结构师，不是读图能解决的 |
| **消防性能化设计评审** | 需要专项资质与模拟软件 |
| **造价审核 / 结算审计** | 属于成本条线，本 Skill 只把清单问题"转出去"，不做造价判断 |
| **需要注册师签章的正式审查** | 本 Skill 出的是**预审报告**，不替代法定审查 |
| **纯扫描件 / 无文字层的图片** | 能读但准确率大幅下降，必须人眼复核（会明确标【需人工复核】）|
| **要求"审出所有问题"** | 不承诺穷尽，承诺的是"该做的动作做完、产物交齐、边界说清" |

### 其他边界

- ⛔ **不含作者本人真实项目迭代出来的经验条目**（那部分属进阶版）
- ⛔ 图纸数据本身缺失 / 损坏 / 是扫描件时，谁都审不了 → **如实进《未执行清单》**，不许装作查了
